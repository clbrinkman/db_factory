# DB Factory

用真实仓库与户外园区的实体，浏览数据库元数据、字段映射和局部血缘。
当前全部数据为模拟数据，没有连接企查查内部系统，也没有运行采集、SQL 或数据库写入。

## 本地运行

需要 Node.js 20+：

```sh
npm ci
npm test
npm start
```

打开终端打印的本地地址（默认 http://127.0.0.1:4173）。也可单独执行 `npm run build`，
将生成的 `dist/` 交给静态服务器。Three.js 随构建本地打包，运行时不依赖 CDN。
这里没有自动发布线上网站。

## 实体语义

- TiDB：正式档案库。源表货箱常驻。
- Hive：包含 ODS、DWD、hive_tmp 的数据园区。
- ODS：T+1 同步收货区；不表示实时同步。
- DWD：ODS 镜像保管区，不默认当作清洗层。
- hive_tmp：可删改的分析工坊；原型仅演示操作。
- 户外来源登记站：来源与采集任务，不等于数据库。
- 围合堆场：数据库；内部货箱：表；运输载荷：批次/副本。
- 质检站与隔离库：保留异常及其来源；正式入库规则未确认，不虚构通向 TiDB 的血缘。

点击“户外”聚焦接入园区，点击库、表、叉车或工作台查看对应信息。
目录与详情默认收起，按需打开透明浮层。血缘只展开所选表附近的有向关系。
三维初始化失败会明确切换到二维兼容模式，不假装仍处于三维。

## 面向巨大目录

默认构建使用按需生成的 **10,000,004 张模拟表**、**8,333,337 条模拟血缘**。
这是可寻址的逻辑规模，不是把这些记录全部放进浏览器：

- 分页默认每页 12 张表，深分页直接计算索引。
- 表元数据 LRU 缓存最多 512 条。
- 完整库表名直接定位；模糊搜索最多扫描 10,000 条，并明确显示“部分匹配”。
- 全局模糊搜索可能在前面的库耗尽预算；应限定库或输入完整表名。生产版本必须接元数据检索服务。
- 血缘沿入边/出边索引遍历，不扫描全量边；最多访问 256 个节点、1,024 条邻接边。
- 三维局部图最多显示 24 个节点、64 条边；截断与遍历预算耗尽都会提示。

这些限制验证的是前端算法与接口行为，**不代表真实数据库端到端性能、网络、权限或吞吐已验证**。

## 验证

`npm test` 先构建，再运行：

1. 22 项目录、字段、血缘与车辆运动检查。
2. 7 项按需目录、深分页、精确查找、搜索预算、缓存和极端扇出检查。
3. jsdom + Three.js 场景图检查：成功初始化、库缺失、WebGL 失败三个分支；
   暂停、视图切换、来源/表/血缘跳转，以及 120 秒仿真中的静态障碍物净距。

场景图测试使用替代渲染器，不生成 GPU 像素，**不是实际浏览器画面验收**。
新车辆目前依靠分离作业区与单车环线保持距离，尚不是多车动态避障系统。

## 目录

```text
src/warehouse.html       场景、模拟目录和交互源文件
src/lazy-catalog.js      按需目录适配器与有预算的血缘遍历
scripts/build.cjs       生成可独立运行的静态项目
scripts/serve.cjs       只绑定 127.0.0.1 的本地静态服务器
test/                   目录、规模与场景图回归测试
docs/semantics.md       实体语义与历史验证记录
docs/NEXT.md            后续迭代和接入边界
```

只提交模拟数据和源代码。不要提交内部数据库凭据、业务数据、未脱敏元数据或来源文档。
