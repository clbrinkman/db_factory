# 后续迭代

## 已完成的可复现基线

- 室内库房、户外来源站/堆场/质检/隔离/月台以及分离运输路线。
- 固定页面大小、按需模拟元数据、LRU 上限和有预算的邻接遍历。
- Three.js 本地打包，摆脱运行时 CDN 可用性依赖。
- 可在新机器通过 npm ci / npm test 复现的测试。

## 下一阶段：真实元数据适配器

不要直接让浏览器连接 TiDB，也不要从表名相似性推断已确认血缘。
先接一条脱敏目录链路：来源、库、表、字段、已确认调度血缘与文档引用。

建议接口边界：

- summary：库/层/域数量；不返回所有表。
- tables：稳定排序、游标分页、按库/业务域筛选。
- search：服务端索引、结果游标、耗时预算、取消过时请求。
- neighborhood：table_id、方向、深度、节点/边预算；显式返回截断标志。
- fields：按表按需返回字段与来源证据。
- runs：真实任务状态驱动运输；未知状态不能用循环动画伪装成成功。

所有接口必须带权限过滤、版本/快照语义和稳定 ID。浏览器只保留有限缓存，
并使用请求序号或取消信号避免旧响应覆盖新选择。已有纯模型测试不验证这些服务端能力。

## 下一阶段：场景与语义

- 从“系统 → 层/业务域 → 库 → 表 → 字段”逐层钻取，远景只显示聚合。
- 用实例化绘制和资源复用进一步降低多库切换开销；测量而非猜测帧率。
- 拆分原型单文件，分离目录适配器、视图状态、场景实体与任务时间轴。
- 工人跨库手动搬运仍是简化直线路径；真实多任务需要统一占用/让行调度。
- 核实浏览器检查的可用授权通道后再做像素/交互验收；不要绕过已有浏览器安全限制。

## 安全与发布边界

本项目不含真实爬虫、SQL 执行、正式库写入或安全扫描。
安装 Strix 与执行主动安全测试是不同授权范围；没有明确目标和授权时不发起扫描，
也不把公司的数据或代码上传到第三方服务。
